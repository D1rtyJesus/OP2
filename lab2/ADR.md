ADR-001: Відокремлення атрибутів Snake від Character та стратегія розв'язання конфліктів канону

Контекст

У попередній ітерації атрибут final_status дублювався в сутності Snake, що порушувало 3НФ реляційної схеми першої лабораторної роботи. Крім того, зовнішнє API від Konami періодично постачає оновлені канонічні дані, які можуть суперечити історично зафіксованому лору.

Рішення

Атрибут final_status закріплюється виключно за сутністю Character.

Сутність Snake пов'язується з Character через зовнішній ключ Snake.character_id = Character.id зі збереженням специфічних атрибутів (codename, is_clone).

До Character додано прапорець has_canon_conflict: boolean (дефолт false).

При отриманні відмінних даних від Konami Archive API система застосовує нові дані авторитетного джерела як активні, проте перемикає has_canon_conflict = true, попереджаючи читача про наявність розбіжності.

Наслідки

Позитивні: Нормалізована схема даних; прозоре інформування читача без втрати узгодженості з офіційним API.

Негативні: Необхідність виконання операцій JOIN між Snake та Character при вибірці клонів за їхнім статусом.

ADR-002: Відмова від використання GenAI для авторепарації сюжетних дір та обмеження скоупу канону

Контекст

Розглядалася ідея підключення LLM/GenAI для автоматичного виявлення і пояснення сюжетних парадоксів франшизи MGS (наприклад, стан Big Boss між MG2 і MGS4). Також постало питання включення неканонічних ігор серії.

Рішення

Винести будь-яку генеративну автоматизацію виправлення сюжетних парадоксів у статус Out-of-Scope.

Обмежити реєстр Game лише канонічною хронологією Хідео Кодзіми; ігри Metal Gear Survive, Metal Gear Acid 1/2 та Snake's Revenge повністю відсікаються.

Наслідки

Позитивні: Нульовий ризик галюцинацій моделі у фактологічній базі знань; детермінована логіка сортування chron_order (1 гра = 1 унікальний індекс).

Негативні: Сюжетні нестиковки не пояснюються системою автоматично, а лише сигналізуються через прапорець конфлікту.

ADR-003: Обробка конкурентності синхронізації та політика кешування при відмові API

Контекст

При масовому або повторному виклику ендпоінта синхронізації існує ризик стану гонитви (race condition). При падінні зовнішнього шлюзу Konami читачі ризикують отримати 502/503 помилки замість каталогу.

Рішення

Впровадити блокування рівня запису на час виконання транзакції синхронізації. Паралельні запити до того самого запису отримують негайну відповідь HTTP 409 Conflict.

Встановити кешування відповідей API з TTL = 24 години.

У разі недоступності API повертати закешовану версію запису, додаючи HTTP-заголовок X-Data-Status: STALE.

Наслідки

Позитивні: Гарантована цілісність даних при паралельних запитах; висока доступність каталогу для читачів навіть за повної відмови зовнішнього сервісу.

Негативні: Необхідність додаткового механізму менеджменту блокувань та валідації актуальності кешу на шлюзі.
